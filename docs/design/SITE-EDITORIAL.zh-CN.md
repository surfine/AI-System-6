# 站点编辑语域

<!-- doc-claims: mixed | audited: 2026-11-02 -->

本合约管辖 AI System 6 的阅读表面：官网、博客和公开文档。它不管产品 UI；产品 UI 遵循
[DESIGN.zh-CN.md](DESIGN.zh-CN.md)，也不管内部设计/运维笔记。README 和 CHANGELOG 只保留
基本排版要求。

这份语域描述目标状态。已有页面在被改动时向它靠拢；本合约不是一次性重做整站的许可。

## 语域

站点是阅读表面，不是桌面隐喻，也不是通用 SaaS 落地页。读者应该能读完一篇文章、理解一次
发布，或跟完一份文档，而不需要再学一套界面。

- 一页一个论点。标题说出它，第一段支持它。
- 阅读优先于 chrome。正文不套 System 6 窗口框。
- 产品截图是标明来源的真实捕获；草图标 `Mockup`，生成图标 `Illustration`。
- 平坦表面、一个强调色、充足留白。不要渐变 hero、三个等宽 feature cards、dashboard card
  grid、嵌套卡片或装饰性 glass。
- 亮色和暗色都是一等状态。页面不能依赖彩色底才能读。

## 字体

| 角色 | 字号 | 字重 | 行高 |
| --- | --- | --- | --- |
| 页面标题 | 32–40px | 500 | 1.2 |
| 章节标题 | 22–26px | 500 | 1.3 |
| 小节标题 | 18–20px | 500 | 1.4 |
| 正文 | 16–18px | 400 | 1.7–1.8 |
| 次要文字 | 14–15px | 400 | 1.6 |
| 图注／元数据 | 12–13px | 400 | 1.5 |

正文用项目拥有的编辑 serif；导航、按钮、标签、代码和表格用 sans。用有真正斜体、节奏安静的
正文 serif，不要用 display face。项目没有自己的正文 serif 时，用系统 serif 栈，不要为此抓
网络字体。产品仍用 System 6 字体；站点是另一种阅读表面，不是把应用换一层皮。

- 句首大写。不要全大写、不要 Title Case、不要句中加粗。
- 界面用系统 sans，正文用项目拥有的 serif；代码和标识符用系统 mono。不要用页面离线就活不下去的
  网络字体。
- 中文和拉丁文都要有可读的回退；在 360px 和正文最大宽度检查断行。
- 正文每行 60–72 字符。长文用单栏，不用双栏杂志网格。
- 链接不能只靠颜色区分：下划线、字重或带可访问名称的图标。

## 年代线索

正文保持现代、可读。历史还原放在外围的编辑部件上：

- 标题、kicker 和页码可以用符合年代的字体与间距；正文仍是一种现代正文 serif。
- 分隔线、图注、图号和小编饰可以用该年代的线条语言，包括 1-bit 细线。
- 强调色留在纸白／墨黑／氧化红棕家族里；年代页可以调温度，不换整套色板。
- 插图和示意图可以借用年代的线条语言，但仍标注为插画，不冒充截图。
- 代码、表格、控件和正文保持现代、可访问。

写 1984 的页面不会变成 1984 的应用窗口。年代是阅读线索，不是戏服。

## 版式

- 文章栏最大 680–760px，窄屏流式。页面可以比正文宽；正文不拉伸填满。
- 文章头：kicker、标题、dek、日期、作者或阅读时间。不要全幅渐变 hero。
- 长文目录必须反映真实标题顺序。
- 图放在阅读栏或更宽的图版里，带图注和来源。不要把图漂到第二个侧栏。
- 代码块横向滚动；页面永不横向滚动。
- 表格在手机宽度变成堆叠行，不做被裁切的网格。
- 脚注和参考在文末可见；上标不是通往来源的唯一路径。
- 分页或上一篇/下一篇用文章标题，不只写 “Previous”。

## 颜色与材质

站点色板是纸白、墨黑加一个氧化红棕强调色——低彩度的砖红／氧化色，不是鲜红。用于链接、
当前小节和一处强调；不要用它填大面积表面。强调色只放在一个 token 里，不要在每个组件里散落
第二种红。产品保留自己的 System 6 蓝和材质令牌。

- 一个中性 ramp 加一个强调色。语义色只用于真实状态：错误、警告、成功或数据分类。
- 正文对比度至少 4.5:1；大字和有意义图形至少 3:1。
- 不要渐变文字、装饰性 glass cards、投影、噪点或发光。
- 功能性焦点环用 outline，不用 shadow。
- 代码、表格和 callout 用细边框加轻微表面变化，不另起一套色板。

## 组件

- **文章头**：kicker、标题、dek、元数据。
- **目录**：真实标题；当前小节用文字标记，不只靠颜色。
- **Callout**：note、warning 或 result 之一；一段短文字。
- **图**：图片或 SVG、图注、来源；图内不放解释段落。
- **代码块**：语言标签、带可访问名称的复制动作、不造成页面横向溢出。
- **表格**：表头、等宽数字、单位和来源的 caption。
- **参考列表**：编号或链接；不依赖 JavaScript 也能到达来源。
- **上一篇/下一篇**：文章标题和方向。

## 图表、示意图与插画

- 示意图、图表、中性草图和插画遵循 `visual-creation` 技能。
- 公开文档用静态 SVG 或渲染好的 PNG；只有宿主真的渲染 HTML 时才用交互 HTML。
  GitHub Markdown 不执行 HTML。
- 写明来源、日期范围、样本量和单位。不要编造趋势或产品状态。
- 产品截图必须是从指定构建真实捕获的。重绘或生成图要标注，且永不冒充观察到的 UI。
- 发布说明里的图表遵循图表模块的数据规则；装饰性 sparkline 不是证据。

## 动效

- 动效可以揭示读者造成的变化，或进入某节的短过渡。150–200ms、ease-out 足够；只做状态变化。
- 阅读页不要 page-load choreography、parallax、自动播放 carousel 或环境循环动画。
- 尊重 `prefers-reduced-motion: reduce`；移除非必要过渡。

## 无障碍

- 一个 `h1`；标题层级递进；有导航的页面提供 landmark 和 skip link。
- 每张图都有文本替代；装饰图用空 alt，且不要给它一个假装是证据的图注。
- 键盘顺序与阅读顺序一致；焦点可见。
- 不只用颜色承载含义。
- 页面设置 `lang`；行内语言切换也标注。
- 代码块或表格的用途不明显时，提供 caption 或可访问名称。

## 文案

- 直接、绑定对象的写法。不要 `elevate`、`seamless`、`next-generation`、`unleash`、
  `game-changer` 或含糊的 `AI-powered`。
- 句首大写；中文用「」和全角标点；英文用直引号。
- 每个事实性主张都有来源或观察到的产物。发布说明写出版本和用户可见变化。
- 改过的规范页面要两种语言同时上线。未经审校的机器翻译是草稿，不是发布页。
- 日期、版本和产品名遵循仓库命名规则。

## 禁止的默认做法

- 带渐变背景的居中营销 hero。
- 三个等宽 feature cards。
- 阅读页上的 dashboard card grid。
- 嵌套卡片。
- 文字背后的装饰性 glass 或 blur。
- 渐变文字。
- 自动播放 carousel 或打字机效果。
- 把产品草图当截图展示。
- 没有来源、单位或样本量的图表。

## 验证

- `npm run site:check`：站点构建和公开表面规则。
- `npm run verify:docs`：规范文档及其中文镜像。
- 在 360px、768px 和 1280px，亮色和暗色下渲染改动页面。检查横向溢出、行长、对比度、
  焦点和链接目标。
- 对任何自包含 HTML 视觉运行 visual-creation 检查器：
  `node ~/.agents/skills/visual-creation/scripts/check-artifact.mjs <file>`。
- 报告检查了什么、什么仍未验证。
