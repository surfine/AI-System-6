# 形态：这张桌子落在哪些玻璃上

`CLAUDE.md` 仍是顶层事实来源，[DESIGN.md](DESIGN.md) 是设计操作合约。本文件是尺寸合约：这个产品落到每一种玻璃上时保留什么、丢掉什么。它存在的意义是让新的屏幕尺寸成为一次决定而不是一次意外——承载不了整张桌子的尺寸，会被告知它承载什么，而不是得到一份什么都缩小了的副本。

## 已经在执行的那一条规则

圆角由两方分别拥有。时代拥有屏幕**内部**的圆角：System 6 是方的，Liquid Glass 是柔和的 16px，每个样式表都用 `--surface-radius` 表述这件事。显示器拥有它**边缘处**的圆角，因为那里显示器自己的曲线就是那个圆角：一个全出血的面如果自己去圆那条边，就会在设备的圆角里再画一个小一号的半径。

Apple 要求全出血界面「accommodate the corner radius, sensor housing, and features like Dynamic Island」（Layout › Phone），并且把系统自己的遮罩描述为与「the curvature of other rounded interface elements throughout the system and the bezel of the physical device itself」一致（App icons）。按机型硬编码半径的表在设备发布当天就会过期，所以这张桌子用同一个 token 回答——`--edge-radius`，凡是接触到边缘的面都读它；这些角合起来的形状是 `--edge-shape`：位于屏内的两条边取时代的半径，接触到显示器的两条边取显示器的。

不是假设，是量出来的：`tooling/verify-display-corners.mjs` 驱动十二种形态——六种手机姿态、三个手表尺寸、iPad 竖屏与横屏、13 英寸 Mac——在六个时代外观下，逐一询问已绘制的元素：谁的圆角画在了它与显示器共用的那个角上。七十二格，零发现。

## Duo 的笔电姿势

Safari 通过 Device Posture 与 Viewport Segments 两个 API 报告姿势，两者都在功能旗标后面；`window.viewport.segments` 给出两个矩形，它们之间的空隙就是转轴。桌面落在上段，键盘落在下段，两者不共享任何一个像素。旗标没打开时，Apple 菜单提供同一个模式。

手指要有目标，即使画面负担不起。键盘键画出来大约 40px，这是五排键能塞进 313px 机身的原因；每个键把自己的命中区往 4px 的缝里各伸 2px，量出来的目标是 44.5px（设备矩阵的 `iphone-duo-pocket` 是向页面发问「这个点属于哪个键」量出来的）。浏览器标题栏那条规则说的也是同一件事：画出来的控件保持原尺寸，周围的可点区域变大。

同一个姿势折回去就是**书**：两页并排。那里什么都不画，但折缝是保留区域，所以应用页面钉在主轴那一段，而不是横跨接缝——苹果自己的理由是压在折缝上的控件难以按下，而分不干净的 split view 就收成单栏。设备矩阵的书格把类名和 token 手动立起来（Playwright 没有铰链），量的是页面确实在折缝处结束。

折迭姿势在发布时位于 Safari 的功能旗标后面，所以 Apple 菜单用同样的模式手动提供；其余都在能测量的地方测量。

三条规则就是这项设计：

- **一台机器，画在折线两侧。** 机身是装饰，不接收指针；只有工作表面遵守安全区。B 面是屏幕这面：边框是这台机器自己的，桌面坐在开口里。C 面是键盘这面。内屏是 1878×2670 像素，比例 445:313；横过来的 CSS 点是 890×626，竖过来是 626×890。横屏的下半只有键盘，按住键盘就是触控板，字会先隐去。竖屏高度够，掌托上另有一块触控板。贴着铰链的一边是方的。
- **按键留在原处。** 竖屏是状态带、按键、掌托，只有按键滚动。横屏不画掌托；按住按键就是触控板，轻点仍是打字。
- **每套外观一台机器。** System 6 是 Macintosh Portable，System 7 是 PowerBook 170，NeXTSTEP 借用同年的 PowerBook 5300 但用 NeXT 自己的灰（NeXT 没有便携机），Drawing Board 是 Wallstreet，Platinum 是 Lombard，Aqua 是钛合金 PowerBook，Tiger 是末代 15 吋铝合金 PowerBook，Snow Leopard 是 13 吋一体成型，Lion 是 2011 年的 Air，Yosemite 是 2014 年的 13 吋 Retina，Big Sur 是 M1 Air，Liquid Glass 是 14 吋 MacBook Pro。有公布机身宽度的，键距按那台机器自己的宽度换算：170 的 18.63 mm 是 286 mm 里的一份，不是大家共用的一个数。折线把下段高度钉死，所以纵向是压缩的，每台的压缩比写在证据表里。每台还带着认得出的零件：屏幕下缘的型号字（除 14 吋内侧）、自己的键帽形状与颜色、点指装置、铰链，以及 2009 年才出现的黑玻璃边框。材质是自家生成的颗粒贴图与 1px 拉丝，折进样式表当 data URI，不是硬件照片；颜色仍由 token 决定，所以深色、更高对比和强制颜色照样逐台重配。
- **启动器留着。** Dock 与控制条让开——没有哪台便携 Mac 把 Dock 画在键盘上——但桌面图标列是打开应用的地方，HIG 要求每个姿势都能拿到同样的内容。手机流程本来就会在应用占屏时把两条侧栏折起来，那才是唯一需要让开的场合。

这台机器的外面就是 **A 面**，只在合盖时才看得到。合上的 Duo 会报告折起，但只有一块屏要排版，所以外面这一面整片画满：那一代的材质与颗粒、它的铰链或前扣、有睡眠灯的那几代画睡眠灯，其余不发明——标志在 2021 年就离开了盖面，画错的剪影比不画更糟。它默认关闭：合上的手机还是手机，直到有人在 Apple 菜单里要这块盖面；点一下就把手机还回来。开关由 lazy 模块插在它所属的那一行旁边，因为启动预算只为每张桌子都需要的部分付费。

触控板不是触摸层：手指从不碰到它指的东西。横屏时按住键盘，键上的字先隐去，手指移动屏幕里的指针；松手后字回来。竖屏时这块板在掌托上，点一下是在指针处按下，两指按住不动是右键，两指移动是滚动。指针被夹在屏幕那一段里。用键盘把焦点移到按键上按回车、和用手指轻点同一个键，各算一次，且在打字前把光标送回输入框。

已知限制，写出来而不是藏着：键是美式布局，另有 🌐 键交给系统键盘（输入法不可能在这里重建）；触控板拖不出文字选区，选字用 ⇧ 加方向键；双指缩放会放大整页，而机身几何是布局像素；外接键盘能用，但机身不会侦测到它并把自己收起来。

## 每种显示器的圆角归属

- **iPhone、iPad、Watch**：单页流程填满玻璃，所以外壳会接触到显示器的左右与下边缘。那些角归显示器；菜单栏下方的那两个角归时代。composer 是外壳的最后一行，只有在安全区把它垫起来时才保留时代的圆角。
- **Mac**：窗口浮在桌面里，永远不碰玻璃，所以没有要交出去的东西；窗口画的每一个角都归时代。菜单栏确实接触顶边，而在那里，方的角正好由显示器自己的曲线来完成。
- **Watch**：平台不报告任何安全区，因为整块屏幕就是系统拥有的曲线。不能有任何元素指望一个不会到来的边距：每一个接触到边缘的面在那里都是方的，由显示器去圆。

## 手腕

watchOS 不是小号的手机，而这是那个「诚实的答案是更短的产品，而不是更小的产品」的面。平台自己的话：人们「glance at their Apple Watch … performing concise app interactions that can last for less than a minute each」，手表应用应当「support quick, glanceable, single-screen interactions that deliver critical information succinctly」，并且「minimize the depth of hierarchy in your app's navigation」（Designing for watchOS）。

**手腕上的 One More Tune 就是一道题。** 声音就是题目，抬起手腕只有几秒，没有地方放卡片架、学习路线、目录或海报。这一瞥保留：

- 一次一道题、它的录音，以及三个答案而不是四个——拇指在 45mm 屏幕上的容错空间，比手指在手机上小得多；
- 一局三张卡而不是十张，因为十题的局是手机上的会话；
- 本局自己的分数，以及一次重听提示音的点击。

**手腕丢掉什么，以及为什么。** 卡片架、学习路线和开局设置——那是浏览，浏览是手机的活。来源/后台面、版权信息与「确认这条配对」的工作流——那是研究工具。影片窗口、Apple Music 商店链接和分享海报——海报是手机形状的产物，而手腕上的链接无处可去。任何自由文本，以及随之而来的挑战码输入：手腕没有键盘。桌面启动器、MultiFinder 和菜单栏——一瞥没有菜单。

**它怎么交付。** 手表上没有 Safari 应用，也没有任何地址栏；第三方的表应用也不能是一个网页——但系统自己的信息与邮件视图**会打开链接**，用一个可以用表冠滚动的网页视图。所以一局分享出来的题，**今天就能在手腕上通过这个页面玩**，不需要伴随应用：信息里点开 `/go/one-more-tune`，一次点击，这一分钟里这个页面就是表上的应用。（本文件早先的草稿说手表根本打不开网页，owner 指出了这个错误：能打开，只是没法输入网址。）伴随应用能补上的是网页视图给不了的东西——表盘复杂功能、通知、触感；而它要用的对局 API 已经存在：`/api/one-more-tune/round` 与 `/answer` 收挑战编号与题号、不返回答案键。

这让「一瞥的排版」从彩排变成了交付路径，并且是按交付路径测量的：从链接进入、396×484、Chromium 与 WebKit 两个引擎，问答窗口会到最前、题目会出声、没有裁切、不发生滚动。问答样式表里那个档位就是这件事成立的原因——字标让位、页眉不再预留桌面字标的高度、标签行从 28px 长到拇指大小、四个答案排成两行两列，揭晓面的舞台也让出记录盒所需的高度。

**不声称什么。** 目前没有 watchOS 应用——没有表盘复杂功能、没有通知、没有触感，也没有在手腕上输入挑战码的办法：网页视图没有键盘，所以一局只能是「点链接进来」或进不来。上面的规划是给那个应用的合约；而网页这一侧只被要求做到今天能量出来的部分：分享链接在手表尺寸下能打开、能出声，形态能渲染、不横向滚动、触摸目标满足下限、没有任何显示器边缘的圆角被画两遍。

## 未决事项

- 手表尺寸下的桌面启动器：它的第二行被裁掉，所以手腕上的启动器只能靠放得下的部分到达。一瞥本来就没有启动器，所以这是一项规划事项，不是一处排版修补。
- 菜单栏的点击目标：在本次发版之前，任何触摸设备上都是 20–28px 的行高，低于 WCAG 2.2 的 24px 下限；而且这些控件恰好压在窗口关闭盒与缩放盒的正上方，漏点一次就可能关掉一个窗口。现在粗指针会把主题自己的 token 提到 `max(--system-menu-height, 44px)`，菜单栏、它下方的窗口、对话框与挂在它下面的弹出菜单一起让位；Mac 保持 24 与 22，指针不需要这份余量。问答自己的标签行也一起长大：竖屏 28px → 44px，横屏 24px → 36px（横屏是整个产品里最缺高度的地方）。
- 触感：手表伴随应用会用腕上的一次轻敲回答「答对了」，而网页这一侧没有触感。当伴随应用存在时，对局负载应当带上它判断这件事所需的信息。
- 45mm 屏幕的数字表冠是平台用于切换界面的导航方式；网页读不到它，所以这一瞥的三个面留在屏幕上，而不是藏到表冠后面。
- 横屏手机上的揭晓面：实测它的记录盒与底部动作区比 402px 高的屏幕面板多需要约 120–140px，因此这一面会在内部滚动，而题目面与结算面不会。没有任何东西不可达（面板可滚，「学习」菜单里也有继续的方式），但「一屏」在那里还不成立，这是最后一个还不成立的面。手腕上曾有同样的缺陷，现在没有了（见手表档：396×484 下无裁切、面板不滚动）。
